Hier beantragt ihr für euer Schulprojekt die Anmeldung mit dem Schulkonto
(OpenID Connect über `auth-dev.htl-leonding.ac.at`).

[IMPORTANT]
====
*Der Server läuft*, die Anmeldung mit dem Schulkonto ist erprobt. Zwei Einschränkungen:
Der Hostname trägt noch `-dev`, und *Benutzerlisten gibt es noch nicht* — den Bedarf
dafür meldet ihr trotzdem im Antrag.
====

== So läuft es

. link:schueler-leitfaden.adoc[*Leitfaden lesen*] — was ihr bekommt, was nicht, und wie
  ihr die Anmeldung in Angular, Quarkus oder eine Web-Anwendung ohne Framework einbaut.
. link:https://github.com/htl-leonding-college/keycloak-antraege/issues/new/choose[*Antrag stellen*]
  — ein GitHub-Issue mit dem Formular „Client für ein Schülerprojekt beantragen".
  Ihr braucht dafür nur ein GitHub-Konto.
. Ihr bekommt die Antwort im Issue: Client-Kennung und, falls beantragt, die Zugangsdaten
  für die Benutzerliste auf einem sicheren Weg (niemals im Issue selbst).

== Die drei Regeln, an denen Anträge scheitern

* Redirect-URIs brauchen einen *festen Host* — ein nacktes `*` wird abgelehnt.
* Ein *Client Secret* gehört niemals in ein Frontend und niemals in ein Repository.
* Die *Benutzerliste* einer Klasse gibt es nur mit Begründung — und nie direkt aus dem
  Browser, sondern über euer Backend. Für „was darf die angemeldete Person sehen" braucht
  ihr sie gar nicht: Klasse und Rolle stehen im Token.

Warum, steht im Leitfaden.
